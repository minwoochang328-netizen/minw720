> **이 문서는 설계 패널 종합자의 최종안이며, 이후 적대적 검증(회의론자 10명, `docs/08_설계패널_검증.md`)에서 반박·보류된 부분을 본문에 직접 반영해 고쳤습니다.** 고친 곳은 `【검증 정정】` 으로 표시했습니다. 핵심 정정 5가지:

> 4. **VRAM**: 7.22/7.66 GiB 예산은 계산기 가정치. 글로벌 5층(head 512)은 FA MMA 경로에서 K/V 를 f16 으로 풀어 64K 에서 ≈0.25 GiB 추가 → 실사용 ≈6.7 GiB, **Windows 는 7.0 GiB 기준으로 계획**(여유 ≈ +0.3).

**⚠ 반드시 지킬 규칙 (심사 1·2 발견, `llama-quant.cpp` 438행 `tensor_type_fallback` 직접 확인):** `ffn_down_exps`의 ne0 = 704, 공유 `ffn_down`의 ne0 = 2112 — 둘 다 256의 배수가 아님. K/I-quant를 지정하면 **텐서마다 경고를 찍고**(끝에 `N of M tensor(s) required fallback quantization` 요약 — 【검증 정정】"조용히"는 아님) Q6_K→Q8_0, Q5_K→Q5_1, Q4_K→Q5_0, IQ*→IQ4_NL로 바뀐다. 이 텐서들에는 **블록-32 타입(Q4_0/Q4_1/Q5_0/Q5_1/Q8_0/IQ4_NL/MXFP4) 또는 블록-64 타입(NVFP4/Q2_0)만** 명시하고(Q1_0 은 폴백 없이 오류), 양자화 로그에 `not divisible`가 있거나 `n_fallback > 0`이면 빌드 실패로 처리한다. gate/up_exps(ne0 2816 = 11×256)는 K-quant 가능.

2. 유지 집합 = 스크립트 규칙(라틴/ASCII, 한글 4,678 + 자모, 구두점/숫자, 악센트, 그리스) ∪ 모든 special/added/`<…>`(6,324 제어·unused 슬롯 — `<bos> <eos> <pad> <unk> <mask> <|turn> <turn|> <|channel> <channel|> <|think|> <|tool_call> <tool_call|> <|tool> <tool|> <|tool_response> <tool_response|> <|"|> <|image> <image|> <|image|> <|audio> <audio|> <|audio|> <|video|>`) ∪ 256 `<0xNN>` 바이트 ∪ 센서스 count ≥ 1인 모든 id ∪ **한국 법률·의료 코퍼스에서 관측된 한자**. 오름차순 정렬, `old→new` 맵.
3. HF 텐서 슬라이스: `model.language_model.embed_tokens.weight[keep]`(tied → lm_head 따라감); E4B는 `embed_tokens_per_layer`도; **MTP 드래프터 임베딩도 동일 슬라이스**(llama.cpp는 어휘가 다른 드래프트를 거부).
4. `tokenizer.json` 재작성(제거 조각·그 조각이 결과/입력인 merge 삭제, 재번호, `added_tokens` 재번호); `config.json`(`vocab_size`, `text_config.vocab_size`, `vocab_size_per_layer_input`, 모든 `*_token_id`, `eos_token_id [1,106]`), `generation_config.json`(eos, `suppress_tokens`) 갱신. 채팅 템플릿은 문자열 참조 → 무변경.
5. **동일성 테스트**: 보존된 1만 문서에서 구/신 토크나이저의 토큰 문자열이 완전히 같아야 함(다르면 해당 조각 복원 후 반복).

**위험**: 센서스 밖 텍스트(한자, 일본어 인용, 이모지)는 바이트 폴백 → 길어지고 분포 이동(한국어 KLD 게이트가 잡음); HF `Gemma4*` 코드가 원 어휘/특수 id를 가정할 수 있음; 드래프터 수락률 변동; 비 en/ko 사용자 품질 저하(문서화); 라이선스 중립(Apache §4: 수정 파일 고지). **결정: S/A-1 출시본은 OFF(옵션 실험판), E4B Lite는 ON.**

## 7. 한국어 전략 + 8 GB에서의 파인튜닝/QAT 경로

1. **학습 없이 (Day-1)**: 한국어 시스템 프롬프트(경어체 기본, "사용자 언어로 답"), Gemma 기본 샘플링. 측정부터.
2. **E4B Lite SKU — 한국어 학습 루프 [07 §1.2–1.3]** 【검증 정정: Unsloth 문서상 E2B 만 8 GB, E4B QLoRA ≈10 GB(r=8 실측 피크 10.12 GB) → 8 GB 에서는 max_seq 512–1024, r 8, 배치 1, 화면 미연결 GPU 로 먼저 시험; 실패하면 E2B 또는 임대 GPU】: `unsloth/gemma-4-E4B-it-qat-q4_0-unquantized`를 `load_in_4bit=True`(NF4 ≈ 4.5–5 GB), LoRA r 8–16, 0.5–1 K 컨텍스트, `finetune_vision_layers=False`, Unsloth(Blackwell RTX 50 지원, Windows는 torchao 먼저) → bf16 CPU 병합 → `convert_hf_to_gguf.py` → **Q4_0(이 베이스가 QAT로 맞춰진 격자)** + Q8_0 attn + PLE 트림 → §6 게이트(기준: 순정 E4B QAT). Google 지침: "full-precision 미세조정은 QAT-unquantized, 저정밀 배포를 노리는 PEFT는 QAT Q4_0".
3. **오프라인 증류(선택)**: 26B를 `llama-server`로 띄워 한국어 프롬프트의 top-k logprob(`n_probs`)를 덤프 → E4B 학생을 오프라인 학습(DistillKit). 같은 토크나이저 → 정렬 불필요. Apache-2.0이라 파생 flow-down 없음. E4B에서는 미검증 → 게이트로 판정.
4. **26B가 G4/G5 실패 시 — QAT 격자 보존 LoRA**: `…-qat-q4_0-unquantized`, 임대 A100/H100 80 GB(【검증 정정】Unsloth: 26B-A4B 는 QLoRA 비권장, 16비트 LoRA >40 GB), LoRA r 16을 **`q,k,v,o_proj` + 공유 MLP에만** → 델타는 Q8_0 텐서에 떨어져 재양자화 오차가 작음(【검증 정정】전문가가 "QAT 격자와 바이트 동일"하다는 가정은 하지 말 것 — G1 재측정). 학습 시간·비용은 데이터량에서 측정(근거 있는 추정치 없음). 배포: 병합판 또는 `convert_lora_to_gguf.py` → `--lora`(gemma4 MoE에서 미검증 → 병합판 기본).
5. **위 LoRA로도 지식 격차가 안 닫히면(지식은 주로 전문가에 있음 — 심사 1 경고)**: 전문가까지 포함한 LoRA를 QAT-unquantized에서 → Q4_0 재양자화 → G1–G6 재게이트. 그래도 실패면 **B-2 A.X 3.1 Light / B-3 Mi:dm 2.0 라우팅**(`llama-swap`; 32 GB에선 순차, 64 GB에선 병행).
6. **재판매 가능한 학습 데이터만** (07 §1.4): MarkrAI/KoCommercial-Dataset (MIT), HAERAE-HUB/qarv-instruct-ko (Apache-2.0), HAERAE-HUB/HRM8K (MIT), beomi/KoAlpaca-RealQA (CC BY-SA), maywell/korean_textbooks (Apache-2.0), kowiki (CC BY-SA) + 자체 도메인; AI Hub는 로컬 학습만·재배포 금지·출처 표기. **금지**: KoAlpaca v1.1a, KULLM-v2, Evol-Instruct-Code-ko, NC/ND 전부, **Kanana-2 출력·가중치를 교사/합성데이터로 쓰는 것**(【검증 정정】§1.8·§3.1(v): 학습한 모델이 Kanana 파생물이 되어 재판매 제한·"Kanana" 이름 접두를 물려받음).

1. **C의 GPU 6.20 → 6.45 GiB** (공유 MLP Q8_0 과소계산, 여유 +1.02 → +0.77). Linux 기본 ncmoe 22 → **23**.
2. **B-HiFi 레시피 불가능**: ffn_down_exps Q6_K → Q8_0 강제 폴백. A-2는 down Q8_0 명시, 19.62 GiB, 20–26 tok/s.
3. **A의 Windows 기본 명령 불가**(7.32 > 7.22, `-c 12288`도 −0.07). Windows는 **A5-W + `-ub 256`(+0.35)** 또는 A5-trim.
4. **B의 한국어 처리량(17–22 글자/초)·80 K 트리밍(−0.51 GiB) 기각** — 측정 센서스와 모순. 25 tok/s ≈ 28–31 음절/초; 트리밍은 172,632행, 26B −0.25 GiB(+버퍼 −0.18).
5. **Gravity-30B-A5B 판매 목록에서 제거**(GLM-4.5 초기화 토크나이저 = 중국 모델 구성요소).
6. **B의 속도 티어 imatrix 기본 적용 기각** — QAT 격자에는 RTN 기본, imatrix는 A/B.
7. **B의 `--fit on` + 명시 인자 조합 무력** — 고객 PC용 명령에서는 인자를 비워야 함.
8. **A의 "12B는 26B와 ~4pt 이내"** 과장 — MMLU-Pro 5.4, AIME-26 10.8, LCB 5.1 차이.
9. **C의 "라이선스 해결됨"** 과장 — 미열람, 판매 전 조치 항목.
10. **【검증 정정】 적대적 검증(회의론자 10명) 후 고친 것**: RTN Q4_0 ≠ QAT 격자, 704 폴백은 "조용하지 않음" + 블록-64 허용, 전문가 읽기 0.75 GiB @ 4.5 bpw, FA D=512 스크래치 ≈0.25 GiB, 예산은 가정치(Windows 7.0 기준), 9700X 23–32 tok/s, 4060 Ti/Ollama 근거 정정, E4B QLoRA ≈10 GB, 26B LoRA >40 GB, Kanana §4.2/§9.4 해석. 상세: `docs/08_설계패널_검증.md`.
