# 08 — 설계 패널과 적대적 검증 결과

> 2026-11-06. 리서치 보고서 8편을 놓고 **아키텍트 3명 → 심사 3명 → 종합 1명 → 회의론자 10명** 이 차례로 작업했습니다(에이전트 17명, 도구 호출 449회). 아키텍트 3명은 서로 다른 관점에서 설계안을 썼고, 회의론자는 종합안을 떠받치는 핵심 주장 16개를 **주장마다 2명씩 따로** 반박을 시도했습니다. 최종 계획은 `docs/09_최종계획_설계패널.md`, 이 문서는 **그 계획이 어떻게 정해졌고 무엇이 틀렸다고 밝혀졌는지**를 기록합니다.

## 0. 요약

- **심사 3명 모두 같은 안(C, "판매용 한국어 우선")을 1위로 뽑았습니다.** 결론은 README 와 같습니다. **S 티어는 Gemma 4 26B-A4B**(Apache-2.0)이고, 전문가만 DDR5 에 두고 GPU 에는 8비트 경로를 올리는 MoE 하이브리드입니다.
- 1위 안에 다른 두 안의 장점을 붙였습니다.
  - 아키텍트 A 에서: Gemma 4 12B 완전 상주 + 공식 MTP 드래프터를 **속도 SKU(A-1)** 로 추가.
  - 아키텍트 B 에서: 64 GB RAM 전용 **HiFi64(A-2)** 추가.
  - 한국어 게이트를 더 엄격하게(Ko-IFEval ≥ 75, A.X 3.1 Light 이상, 한글 충실도).
- **검증 결과: 16개 주장 중 4개 확인, 6개 반박(일부 포함), 6개 보류**(확인과 보류가 갈린 2개 포함).
  - 가장 큰 정정: **"Google QAT 체크포인트를 llama.cpp RTN Q4_0 으로 바꾸면 학습된 4비트 격자가 그대로 재현된다"는 전제는 틀렸습니다.** 심사 3명이 모두 이 전제를 근거로 C 를 칭찬했지만, 검증에서 뒤집혔습니다.
  - 그래서 S 빌드는 **RTN, imatrix Q4_0, 공식 QAT GGUF 세 후보를 한/영 KLD 로 비교해 고르는 방식**으로 바꿨습니다. 첫날은 Google/Unsloth 공식 QAT GGUF 를 그대로 씁니다.
- **8 GB 에서 E4B 한국어 QLoRA 를 학습할 수 있다는 주장도 약해졌습니다.** Unsloth 문서상 8 GB 에서 되는 것은 E2B 이고, E4B 는 약 10 GB 가 필요합니다.
- **속도 예상**: 9700X 실측은 아직 없습니다. 지금 계획치는 **23~32 tok/s(미측정)** 이며 첫 측정으로 보정해야 합니다.

## 3. 심사 점수 (70점 만점)

| 심사위원 | A | B | C | 1위 |
|---|---|---|---|---|
| 1. 시스템 엔지니어(실현성·수치) | 52 | 50 | **56** | C |
| 2. ML 품질 연구자(양자화 충실도) | 55.5 | 50 | **58** | C |
| 3. 제품·법무(재판매·한국어·운영) | 54 | 50 | **57** | C |

심사위원이 찾아낸 사실 오류 중 최종안에 반영된 것:
- **704 열 폴백(심사 1·2)**: Gemma 4 26B 의 전문가 폭이 704 라 `ffn_down_exps` 에 Q6_K 를 지정해도 Q8_0 이 됩니다. B 의 파일 크기·속도가 모두 틀어졌고, 이를 고친 HiFi64 레시피를 따로 만들었습니다.
- **공유 MLP 과소 계산(심사 1)**: 계산기가 공유 밀집 MLP(0.535B)를 기본 비트로 계산합니다. C 의 GPU 사용량을 6.20 → 6.45 GiB 로 고쳤습니다. 보정 프리셋 `gemma-4-26b-a4b-sq8` 은 `tools/presets.json` 에 있습니다.
- **A 의 Windows 기본 명령 초과(심사 1·2·3)**: Windows 에서는 A5-W(Q4_K 임베딩) + `-ub 256`(6.87 GiB)이나 어휘 트리밍판을 씁니다.
- **"12B 는 26B 와 4점 이내"는 과장(심사 3)**: 실제 차이는 MMLU-Pro 5.4, AIME-26 10.8, LCB 5.1 점입니다.
- **`--fit on` 과 명시 인자를 함께 쓰면 무력(심사 1)**: `--fit` 은 지정하지 않은 인자만 조정합니다.

## 6. 여전히 열려 있는 것 — 숫자가 계획을 바꾸는 순서대로 측정

1. **`nvidia-smi` 유휴 VRAM**(Windows 데스크톱 예약) → `--n-cpu-moe` 결정.
2. **`llama-bench -ncmoe 30,26,24,22 -d 8192`**(공식 QAT GGUF) → 9700X 실효 대역폭과 S 의 실제 tok/s(계획 23~32).
3. **S 후보 KLD(한·영 분리)**: RTN Q4_0 / imatrix Q4_0 / Google QAT GGUF / Unsloth QAT GGUF → 출시 파일 선택.
4. **한국어 절대 수준**: KMMLU 층화 900문 + HAE-RAE + Ko-IFEval 로 Gemma 4 26B-A4B 와 A.X 3.1 Light 비교(같은 하네스). Gemma 4 의 한국어 수치는 이 측정 전까지 **0개**입니다.
5. **E4B QLoRA 가 8 GB 에 들어가는지**: max_seq 512~1024, r 8, 배치 1, 모니터를 연결하지 않은 상태. 안 되면 E2B 또는 임대 GPU.
6. **MoE + MTP, `--moe-cache-mib` A/B**: 이득이 확인되지 않아 기본값은 끔.
7. **Gemma 4 라이선스 페이지 원문**: 제한 없는 네트워크에서 읽고 PDF 로 보관(판매 전 필수).
