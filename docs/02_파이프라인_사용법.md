# 02. 파이프라인 사용법 — 다운로드 → 변환 → imatrix → 혼합정밀 양자화 → KLD 검증 → 벤치 → 서빙

이 저장소의 스크립트는 **2026-11-04 기준 llama.cpp master 소스**(`common/arg.cpp`, `tools/quantize/quantize.cpp`,
`tools/imatrix/README.md`, `tools/perplexity/README.md`, `tools/llama-bench/README.md`)에서 플래그 이름을 직접 확인해 작성했습니다.
GPU 가 없는 환경에서 작성되었으므로 **실행 검증은 사용자의 5060 Ti 에서 처음 이루어집니다.** 플래그가 바뀌면 `llama-server --help` 로 대조하세요.

## 0. 준비

| 항목 | 내용 |
|---|---|
| OS | Linux(권장) 또는 Windows 11 (WSL2 도 가능). Windows 는 데스크톱 합성기가 VRAM 0.5~0.9 GiB 를 선점 → Linux 가 같은 8GB 로 더 큰 컨텍스트 |
| 드라이버/CUDA | RTX 50(Blackwell, `sm_120`) 은 **CUDA 12.8 이상** 필요. 13.x 권장 |
| 파이썬 | 3.10+ ; `pip install -U "huggingface_hub[cli]" gguf datasets` |
| RAM | MoE 전문가를 CPU 에 두는 하이브리드 구성은 32GB 로 충분(gpt-oss-20b 13GB, Gemma 4 26B-A4B 4비트 ~15GB). 64GB 면 F16 원본 변환·imatrix 가 편해짐 |

```bash
# llama.cpp 빌드 (Linux/WSL2). Windows 는 scripts/00_build_llamacpp.ps1 또는 Releases 의 cuda-13 zip
bash scripts/00_build_llamacpp.sh
export PATH="$HOME/llama.cpp/build/bin:$PATH"
llama-server --list-devices      # CUDA0: NVIDIA GeForce RTX 5060 Ti (8 GiB) 확인
```

## 1. 모델 내려받기

```bash

bash scripts/10_download.sh google/gemma-4-E4B-it "*" models/gemma-4-E4B-it
```

## 2. 원본 → GGUF(F16/BF16) 변환

```bash
cd ~/llama.cpp && pip install -r requirements.txt
python convert_hf_to_gguf.py ../models/gemma-4-E4B-it --outtype bf16 --outfile ../models/gemma-4-E4B-it-bf16.gguf
# 비전 타워가 있는 모델은 --mmproj 로 프로젝터를 따로 뽑을 수 있음(텍스트만 쓸 땐 생략 → VRAM 절약)
```

## 3. 캘리브레이션 세트(한국어+영어+코드) 와 imatrix

```bash
python calib/build_calibration_set.py --target-chars 6000000 \
    --out calib/calibration_ko_en_code.txt --holdout calib/eval_holdout.txt
#  └ 자신의 도메인 텍스트가 있으면 --extra my_docs.txt (가장 효과 큼)

CTX=2048 CHUNKS=256 bash scripts/30_imatrix.sh models/gemma-4-E4B-it-bf16.gguf
#  MoE 모델이면 자동으로 --cpu-moe (전문가는 RAM, 어텐션만 GPU) → 8GB 에서도 F16 원본으로 imatrix 가능
```

왜 imatrix 인가: 3~4비트 양자화는 "어떤 가중치를 정밀하게 남길지"가 전부입니다. imatrix 는 캘리브레이션 텍스트의
실제 활성화 통계로 그 중요도를 재서 IQ/K-quant 의 반올림을 보정합니다. **한국어가 캘리브레이션에 없으면 한국어가 먼저 망가집니다.**

## 4. 혼합정밀(mixed-precision) 양자화

```bash
# 예 1) MoE 하이브리드: 전문가는 RAM(4비트대), GPU 상주 어텐션은 q8_0
bash scripts/40_quantize.sh models/gemma4-26b-bf16.gguf models/gemma4-26b-HYB.gguf IQ4_XS \
     recipes/moe_hybrid_8gb.tensor-types.txt models/gemma4-26b-bf16.imatrix.gguf

# 예 2) 밀집 4~9B, GPU 전부 상주
EMBED_TYPE=q6_k OUTPUT_TYPE=q6_k bash scripts/40_quantize.sh models/x-bf16.gguf models/x-UD.gguf IQ4_XS \
     recipes/dense_gpu_8gb.tensor-types.txt models/x-bf16.imatrix.gguf

# 예 3) Blackwell FP4 네이티브: 모든 행렬 nvfp4, 민감 텐서만 q6_k (베이스 ftype 은 Q8_0 로 주고 레시피가 덮어씀)
bash scripts/40_quantize.sh models/x-bf16.gguf models/x-NVFP4.gguf Q8_0 \
     recipes/dense_nvfp4_blackwell.tensor-types.txt models/x-bf16.imatrix.gguf
```

레시피 파일 문법과 텐서 이름 규칙은 `recipes/README.md`. `llama-quantize --dry-run ...` 으로 어떤 텐서가 어떤 타입이 되는지 먼저 볼 수 있습니다.

## 5. 품질 게이트: KL-divergence

```bash
# (한 번) 원본 로짓 저장 — 평가 텍스트는 캘리브레이션과 다른 파일!
CHUNKS=64 bash scripts/50_eval_kld.sh base models/x-bf16.gguf calib/eval_holdout.txt models/x.kld
# 양자화본 평가
bash scripts/50_eval_kld.sh eval models/x-UD.gguf models/x.kld
```

판정 가이드(경험적): 평균 KLD **< 0.01** 사실상 무손실 · **0.01~0.05** 양호 · **0.05~0.1** 체감 가능 · **> 0.2** 열화 큼.
같은 파일 크기에서 KLD 가 더 낮은 레시피가 이기는 레시피입니다. 99.9% 분위 KLD 와 `RMS Δp` 도 같이 보세요(평균만 보면 드문 토큰의 붕괴를 놓칩니다).

## 7. 서빙

```bash
llama-server -m models/gpt-oss-20b-mxfp4.gguf -ngl 99 --n-cpu-moe 16 -c 32768 -fa on -ctk q8_0 -ctv q8_0 \
    --fit on --fit-target 512 --jinja --reasoning-format auto -t 8 --host 127.0.0.1 --port 8080
#  --fit on : 남은 VRAM 에 맞춰 미지정 인자(ngl/ctx)를 자동 조정. --fit-print on 으로 예측 메모리 출력
#  --n-cpu-moe N : 앞 N개 레이어의 전문가를 CPU 에. 숫자를 줄일수록 빨라지고 VRAM 을 더 씀 → 60_bench 로 최적점 찾기
```

예산을 미리 보려면:

```bash
python3 tools/vram_budget.py --model gpt-oss-20b --quant mxfp4 --quant-attn q8_0 --quant-output q8_0 --kv q8_0 --ctx 32768 --n-cpu-moe 16
python3 tools/vram_budget.py --sweep --ctx 16384 --kv q8_0 --os windows
```
