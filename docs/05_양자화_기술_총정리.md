## 1. 한 눈에 보는 결론 10줄

1. **NVFP4 는 mainline llama.cpp 의 1급 GGUF 타입**(`GGML_TYPE_NVFP4=40`, 64 가중치 블록 36 바이트 = 4.5 bpw, PR #19769 2026-03-11)이고, Blackwell 네이티브 블록 스케일 MMA(`mma.sync … kind::mxf4nvf4 … ue4m3`, PR #22196 2026-04-28)가 있다 → 이 카드의 FP4 텐서코어는 llama.cpp 로 바로 쓴다. [H]

## 3. `llama-quantize` 로 NVFP4/MXFP4 를 만들면 안 되는 이유, 그리고 공식 경로

**안 되는 이유 [H]**
* `ggml-quants.c` 의 `quantize_nvfp4()`/`quantize_mxfp4()` 는 순수 round-to-nearest 이고 `GGML_UNUSED(quant_weights)` 로 **imatrix 를 명시적으로 무시**한다. (저장소 `recipes/README.md` 의 "imatrix 지원" 문구는 보고서와 모순 → 수정 대상.)
* `llama-quantize` 프리셋에 NVFP4 가 없다(`MXFP4_MOE` 만). 파일 타입 `LLAMA_FTYPE_MOSTLY_NVFP4`(39)는 존재하지만 변환기가 임포트 모델에 붙이는 표지일 뿐이다. `--tensor-type <regex>=nvfp4|mxfp4` 가 받아들여지는 것은 파서가 모든 ggml 타입명을 매치하기 때문. docs/03 가 인용한 "PR #23572 'permit quantizing into NVFP4' 종료(미채택)"는 보고서 01 출처이며 보고서 04 에는 없음 → 본 문서 기준 미검증.
* 그 결과 품질은 Q4_1 급: 최초 NVFP4 PR(#19769)의 Qwen3-4B RTN 측정 PPL 15.25(+8.0 %, F16 14.33) / KLD 0.110 vs Q4_1 15.81 / 0.112. 반면 제대로 캘리브레이션된 NVFP4(ModelOpt max/MSE/Local-Hessian + 선택적 QAD)는 Q4_K_S 크기에서 Q4_K_M~Q5_K_M 사이 품질.

**공식 경로 [H]**
1. 생성: **ModelOpt** `examples/hf_ptq/hf_ptq.py --qformat {nvfp4, nvfp4_awq_lite, nvfp4_mlp_only, nvfp4_experts_only, nvfp4_omlp_only, nvfp4_svdquant, nvfp4_w4a4_weight_mse_fp8_sweep, nvfp4_w4a4_weight_local_hessian, w4a8_nvfp4_fp8, w4a8_mxfp4_fp8, mxfp8, …} --kv_cache_qformat {fp8_cast, fp8, nvfp4_cast, nvfp4, nvfp4_affine, nvfp4_rotate, none} --calib_size 512 --export_path <dir>`(레시피 `--recipe general/ptq/nvfp4_default-kv_fp8_cast`, `--low_memory_mode`; 기본 캘리브레이션 128~512 샘플 cnn_dailymail + Nemotron-Post-Training-Dataset-v2; 레이어별 캘리브레이션으로 단일 GPU 양자화 가능 — 4.9 TB Qwen3.8-2.4T-A95B 를 GB300 1장에서 3 h 04 m, 2026-09-28). gpt-oss 는 `--cast_mxfp4_to_nvfp4` 로 비트 정확한 폐형 캐스트. 또는 **llm-compressor** `QuantizationModifier(scheme="NVFP4")`(활성 전역 스케일에 ~20 샘플 충분) / `NVFP4A16`(RTN, 데이터 불필요) / GPTQ·AWQ-NVFP4 / `QADModifier`. 이 장비 자체로는 어려움(§10 비교표: 24 GB+ GPU 또는 레이어별 CPU 오프로드로 수 시간) → docs/03 의 "클라우드 GPU 에서 PTQ 후 로컬" 과 일치.
2. 임포트: `python convert_hf_to_gguf.py <modelopt-or-compressed-tensors-nvfp4-dir>` — ModelOpt `NVFP4`, `W4A16_NVFP4`, `MIXED_PRECISION`(레이어별 NVFP4/FP8), compressed-tensors `nvfp4-pack-quantized`/`mixed-precision` 처리; FP8 레이어는 Q8 로 유지(#23250); 텐서별 `general.tensor_extra.prec_a4` 플래그 기록. 임포트 PR 계보: #20539(2026-03-16) → #21095(2026-05-25) → #22247, Gemma 4 #21971/#22804, Mistral3 #23629, lm_head #23046, MTP 스케일 #23563, LFM3 #31608(2026-11-03). 저장소 스크립트: `scripts/45_convert_nvfp4_checkpoint.sh`.
3. 빌드: CUDA ≥ 12.8 이면 `120a-real` 자동 포함("Blackwell, needs CUDA v12.8, FP4 tensor cores"); 공개 바이너리는 **CUDA 13.4** 빌드(Windows/Linux)에 포함, CUDA 12.4 Windows 빌드는 불가 → docs/03 §1-6 과 동일 결론.

**5.2 imatrix 모범사례 (`llama-imatrix`) [H]**
* `llama-imatrix -m model-bf16.gguf -f calib.txt -o imatrix.gguf -ngl 99 -c 2048 -b 2048 --output-frequency 10 --save-frequency 50 [--chunks N] [--parse-special]`. 출력은 기본 GGUF(PR #9400); `--in-file a.gguf --in-file b.gguf -o merged.gguf` 로 병합; **`--show-statistics`**(PR #14891)는 텐서별 평균/σ/skew/**kurtosis**/엔트로피/에너지와 레이어별 gain/L2/cosine/PCC 를 출력 — 고첨도·고에너지 텐서가 승격 대상.
* `--process-output` 은 `output.weight`/묶인 `token_embd` 수집(기본 off — "이 텐서들에는 imatrix 를 쓰지 않는 편이 보통 낫다"); **`--nextn`** 은 MTP 레이어 수집(Gemma 4 / Nemotron MTP 헤드에 필요); `--chunk N` 으로 저품질 선두 텍스트 건너뜀.
* 캘리브레이션 데이터 원칙: Wikitext 양은 ~100k 토큰 이후 무의미, 중요한 것은 **도메인/형식 커버리지** — 다국어(한국어 포함)·코드·수학, 그리고 instruct 모델은 **채팅 템플릿 적용 텍스트를 `--parse-special` 로** 파싱. exllamav3 자기 캘리브레이션 연구는 정렬 모델에 자기 생성 채팅/추론 트레이스가 가장 잘 전이됨을 발견했고, Unsloth UD 2.0 도 같은 이유로 채팅 템플릿 인지 혼합 코퍼스 사용 [M]. 청크 길이: 배포 컨텍스트로(역사적 기본 2048; 2025+ 모델에 4096~8192 로 캘리브레이션하는 메인테이너들 [L] → 미검증). 저장소: `calib/build_calibration_set.py`, `scripts/30_imatrix.sh`.
* **imatrix 필수 타입**(`tensor_requires_imatrix`): IQ1_S, IQ1_M, IQ2_XXS, IQ2_XS, IQ2_S, IQ3_XXS, 그리고 Q2_K_S 파일 안의 Q2_K. 나머지는 있으면 사용(Q4_K_M KLD 0.0313 → 0.0282, Q3_K_M 0.1019 → 0.0844). **MXFP4·NVFP4 는 무시**(RTN). docs/03 §4 의 "IQ2_XXS/IQ2_XS/IQ1_S 필수" 는 이 목록의 부분집합이다.
* imatrix 는 전문가별로 저장되고 양자화 청크가 전문가 경계를 넘지 않음(`llama_tensor_quantize_impl`) → MoE 전문가는 개별 캘리브레이션.

**5.3 `llama-quantize` 기본 동작과 오버라이드 (`llama-quant.cpp`) [H]**
기본: `output.weight` → Q6_K(IQ1/IQ2 혼합은 Q5_K; 행 크기가 블록 배수가 아니거나 `MXFP4_MOE` 면 Q8_0); `token_embd` → 혼합에 따라 Q2_K/IQ3_S/Q4_K; GQA ≥ 4 또는 8-전문가 MoE 면 `attn_v`/`attn_k` 승격(Q4_K/Q5_K/Q6_K); Q4_0/Q5_0/IQ4 혼합은 첫 `n_layer/8` 개 `ffn_down` 승격; 8-전문가 MoE 특례; `attn_qkv_gate` 는 qkv 규칙; ≤8비트 잠재/attn-gate 텐서는 Q8_0 강제. 오버라이드: `--output-tensor-type`, `--token-embedding-type`, `--tensor-type "<regex>=<type>"`(반복 가능; `iq4_xs`, `q8_0`, `mxfp4`, `nvfp4`, `bf16` 등 모든 ggml 타입명), `--tensor-type-file`, `--pure`, `--leave-output-tensor`, `--include-weights/--exclude-weights`, `--prune-layers 20,21,22`, `--override-kv <arch>.expert_used_count=int:N`. 30B-A3B 하이브리드(전문가 RAM, 나머지 GPU) 예:
```
llama-quantize --imatrix imatrix.gguf \
  --output-tensor-type q8_0 --token-embedding-type q8_0 \
  --tensor-type "ffn_(up|gate)_exps=iq3_s" --tensor-type "ffn_down_exps=iq4_xs" \
  --tensor-type "ffn_(up|gate|down)_shexp=q6_k" --tensor-type "attn_.*=q6_k" \
  --tensor-type "(ssm|conv|norm|router|ffn_gate_inp).*=q8_0" \
  model-bf16.gguf model-mix.gguf iq3_m 16
```
`ffn_down_exps` 에 up/gate 보다 한 등급을 더 주는 근거가 §9 의 GLM-5.3-Flash 결과다. 저장소의 `recipes/*.tensor-types.txt` 가 같은 기계를 쓴다.

* **Microsoft BitNet b1.58 2B4T**(MIT; 2.4 B, 4 T 토큰, 2025-04-14, arXiv 2504.12285): 삼진 가중치 + 8비트 활성, 패킹 ~0.4 GB. `bitnet.cpp`(`python setup_env.py -md models/BitNet-b1.58-2B-4T -q i2_s` → `run_inference.py -m …/ggml-model-i2_s.gguf -t 16 -cnv`; clang ≥ 18, cmake ≥ 3.22): x86 I2_S/TL2 커널이 llama.cpp F16 대비 **2.37~6.17× 속도, 71.9~82.2 % 에너지 절감**(ARM 1.37~5.07×); 2026-01-15 릴리스에서 병렬 커널·타일링·임베딩 양자화로 추가 1.15~2.1×; 공식 **GPU W2A8 GEMV 커널**(2025-05-20, dp4a, A100 벤치). Zen 5 수치 없음, 커널은 AVX2 → 9700X 에서 돌지만 AVX-512 이득 없음. **더 큰 공식 BitNet LLM 은 없다** — 2026 추가는 1비트 *임베딩* 모델(0.6B/270M, 2026-07-20)과 VibeASR.cpp. bitnet.cpp 표의 커뮤니티 삼진 모델(Falcon3/Falcon-E, Llama3-8B-1.58-100B-tokens)은 *변환* 모델로 품질 손실 큼. mainline llama.cpp 는 TQ1_0/TQ2_0(Vulkan 2026-09 포함), ik 는 IQ1_BN/IQ2_BN. [H]
* **Meta ParetoQ**(BSD 코드, 2025-02): 1/1.58/2/3/4비트 QAT 의 가장 엄밀한 공개 연구. 삼진·2비트가 정확도-크기 Pareto 전선에 있고, 커널 친화성 때문에 디바이스엔 2비트 권장(2비트 CPU 커널이 동일 정확도의 4비트를 이김); 공개는 MobileLLM-ParetoQ ≤ 1.5 B 만(1B: BF16 62.1 → 2비트 61.0 → 1.58비트 58.5). 논문의 8B 삼진은 미공개. [H]
* **PrismML Bonsai 1비트 계열**(2026): 1.7B/4B/8B(+27B, "Ternary-Bonsai-2-27B" 2026-09), GGUF `prism-ml/Bonsai-*-gguf`, **Q1_0**(128 블록·fp16 스케일·부호 비트 = 1.125 bpw; 8B = 1.07 GiB), Hadamard 접힌 가중치(`hadamard_packing.json`, 런타임 `llama_mul_mat_hadamard`); llama.cpp PR #21273(2026-04-06, PrismML-Eng 포크 저자), CUDA #21629/Metal #21528/Vulkan #21539; ik PR #1570(2026-04-02), 삼진 `PQ2_0`/`PTQ1_0`(#2550, 2026-09-29). PR 저자는 "1비트로 학습"(TPU v4)이라 하지만 **아키텍처가 Qwen3 dense 와 동일하고 논문이 Qwen3-8B 를 베이스로 명시한다는 보고** → 사용자 계보 규칙상 Qwen 파생으로 보아 **제외**; 품질 보고도 약함(4B Wiki PPL 16.27, "추론 미작동"). 속도는 극적(4B 141 t/s TG 64-스레드 Threadripper; 8B 32 t/s M4 Pro) → 1비트 + Hadamard + 128 스케일이 지원되는 GGUF 경로가 됐다는 *기술 신호*. [H]
* **deepgrove/maple-preview**("Maple", 20B-A1B 삼진 MoE, TQ1_0/TQ2_0 GGUF; mainline `MapleForCausalLM` 변환기; ik PR #2694 2026-10-19): 공개 GitHub 조직 내용 없음, 계보·라이선스 불명(HF 차단), 커뮤니티 "별로 똑똑하지 않다"; CPU 수치만(i7-6700K PP 465, TG 45 t/s). 계보·라이선스 확인 전까지 비권장. [H 존재]/[L 품질]

## 9. MoE 혼합정밀 원칙과 2026 증거

**합의 규칙(2026 측정으로 뒷받침)**: 라우팅 전문가(파라미터의 85~95 %, 개별 사용 빈도 낮음)는 공격적으로 양자화하고, 토큰별 임계 경로 — 어텐션 투영, 라우터/게이트, 공유 전문가, 초기 레이어의 밀집 MLP, Mamba/conv/SSM 투영, 임베딩, lm_head, norm, MTP 헤드 — 는 6~8비트 또는 BF16 으로 유지.

1. **NVIDIA GLM-5.3-Flash 연구**(Model Optimizer, 2026-10-28) — 321 B MoE, 288 라우팅 전문가에 304 B: 전문가 IQ2_S(2.56 bpw) + 나머지 Q8_0/BF16 은 FP8 대비 6개 벤치 평균 −2.3 ± 0.4점; **전문가 `down` 투영만 NVFP4 로(전문가 평균 3.21 bpw, +0.65 bpw) 토큰당 NLL 오차 ~40 % 감소, 평균 −0.1 ± 0.3**("down 투영이 IQ2 오차의 대부분을 담는다"); QAD 300 회가 장문맥 폭주를 고침(AA-LCR 70.0→74.0, FP8 74.9)이나 지식 회상은 못 고침. 공유 전문가·0~2층 밀집 MLP 는 Q8_0, 어텐션(KDA + sparse MLA)·라우터·비전·MTP·임베딩·lm_head 는 BF16. [H]
2. **Model Optimizer 설정** `NVFP4_MLP_ONLY_CFG`, `NVFP4_EXPERTS_ONLY_CFG`(`*mlp.experts*`, `*block_sparse_moe*` 만), `NVFP4_OMLP_ONLY_CFG`(+`o_proj`) — "민감한 어텐션 QKV 투영을 보존해 NVFP4 PTQ 정확도를 높이는" 벤더 권장 방식; Nemotron 3.5 Super VL 생산 레시피가 정확히 "라우팅+공유 전문가 NVFP4, 어텐션/Mamba in-out proj/lm_head FP8, KV FP8". **AutoQuantize** 가 할당 자동화(`effective_bits` 4.8~5.4, NVFP4+FP8 후보; 융합 QKV/gate-up/한 레이어의 모든 전문가는 그룹 결정); 라우팅 토큰 기반 전문가별 GPTQ Hessian(0.49.0)과 전문가별 imatrix 통계가 표준. [H]
3. **llama.cpp**: `MXFP4_MOE` = 전문가 MXFP4 + 나머지 Q8_0; 기본 믹서가 `attn_v`/`attn_k`/초기 `ffn_down` 승격, 8-전문가 특례; `--tensor-type` 정규식(`ffn_(up|gate)_exps`, `ffn_down_exps`, `ffn_*_shexp`, `ffn_gate_inp`, `attn_*`, `ssm_*`)으로 완전 제어; imatrix 전문가별 수집; NVFP4 임포터가 ModelOpt 의 레이어별 혼합(NVFP4 전문가 + FP8→Q8 어텐션)을 보존하고 W4A16 텐서를 W4A8 로 태깅. [H]
4. **exllamav3**: `-hq`(어텐션·공유 전문가 승격, MoE 에서 +0.05~0.10 bpw 로 "불균형하게 큰" 충실도 향상), `--moe_affinity_eps 0.01`(라우터가 실제 보낸 토큰으로 전문가별 캘리브레이션), `--recipe`(자기 캘리브레이션 최적화기의 텐서별 비트), 전문가 오프로드 시 어텐션은 GPU. [H]
5. **llm-compressor**: `MXFP4xFP8` / NVFP4-전문가 + FP8-어텐션 레시피(GLM-5.3, Nemotron 3.5 Super VL, Qwen3.8), HIGGS ILP, `quantization_non_uniform` 예제(`down_proj` 상위 정밀도), 양자화 전 REAP/MoNe 전문가 가지치기. [H]
6. **Unsloth UD 2.0** 은 같은 원칙을 휴리스틱으로(라우터/공유/임베딩/lm_head 높게, 전문가 낮게) [M]; **ik_llama.cpp** 는 정규식 커스텀 믹스(PR 244)와 GPU 별 auto-fit. [H]
7. **논문**: MxMoE(ICML 2025, arXiv 2505.05799; 전문가별 ILP 비트 할당 + 생성형 혼합정밀 GroupGEMM, RTX 4090·Qwen1.5-MoE 테스트) [H 코드]; MoQE/QMoE/EAQuant/MoEQuant(2023~25) [L] → 미검증. 실무 도구가 결론을 흡수한 상태.

**이 장비용 레시피(30B-A3B 급, 전문가 DDR5, GPU ≤ 8 GB)**: GPU 쪽(어텐션, 공유 전문가, 라우터, norm, 임베딩, lm_head, KV)을 Q8_0/BF16 으로 ≈ 1.5~3 GB; 전문가는 IQ3_S/IQ3_K(gate/up) + IQ4_XS/NVFP4(down) 로 평균 ≈ 2.9~3.5 bpw → 30 B 모델이 RAM 에 10~13 GB; 기대 KLD 0.03~0.06 대(Qwen3.8-Flash-Next UD-IQ3_XXS 0.035 → UD-IQ4_XS 0.017 이 괄호). 벤더가 NVFP4 를 배포하면(Nemotron 3.5 Lightning, Gemma 4 26B-A4B) 대신 임포트: 전문가 4.5 bpw(30 B 에 RAM ~16 GB), KLD ≈ 0.01~0.03, GPU 상주 층은 W4A8/W4A4 프리필. 64 GB RAM 은 전문가를 IQ3 대신 NVFP4/Q5 로 둘 수 있게 할 뿐 방법을 바꾸지 않는다. 비평 08 보충: Unsloth Nemotron 3 Nano Q4_K_M GGUF 는 Mamba/어텐션 텐서를 고정밀로 두어 **24.6 GB(~6.2 bpw)** 이며 32 GB RAM 에선 위험 → 위 레시피로 ~4.5 bpw(17~18 GB 추정) 자가 양자화가 필요(저장소 `recipes/moe_hybrid_8gb*.tensor-types.txt`).

**이 장비에서의 실천 순서(양자화 측면만)**
1. **완전 상주 모델(KV 포함 ≈ 6.5 GB 예산)**: 12 B 밀집의 EXL3 3.0~3.5 bpw(Gemma 4 12B Unified: 12 B × 3.25 / 8 ≈ 4.9 GB + 헤드/임베딩 — 산술 추정 [L calc]) → KLD ≈ 0.03~0.05(GGUF 로 치면 Q3_K_M→Q4_K_S 급을 ~0.7 비트 적게), 또는 8 B 의 EXL3 4.0 bpw → KLD ≈ 0.013. `python convert.py -i <hf> -o <out> -w <tmp> -b 3.25 -hb 6`(MoE 는 `-hq`, 임베딩 축소 시 `-eb 8`). GGUF 대안: IQ4_XS(12 B ≈ 6.8 GB — KV 와 함께는 빡빡) 또는 IQ3_M(≈ 5.6 GB, KLD ≈ 0.10). 비평 08: 8 GB Blackwell 의 EXL3 tok/s 실측·서빙 명령(TabbyAPI, `-cq`, MTP)은 아직 없음 → 로컬 측정.
2. **전문가를 DDR5 에 두는 MoE 20~30 B**: GGUF + imatrix + 텐서별 믹스(§5.3) 또는 벤더 NVFP4 임포트; `llama-server -ngl 99 --n-cpu-moe <N> -fa on`, `GGML_CUDA_MMQ_PREC=auto`(기본). gpt-oss-20b 는 네이티브 MXFP4 GGUF 그대로(비평 08 C19: 필드의 33~35 tok/s 는 Unsloth **F16** GGUF ~13.8 GB 로 측정된 값 → MXFP4 파일로 재측정). Gemma 4 26B-A4B 는 새 Q4_K_M 보다 Google QAT Q4_0 계열 GGUF(+ MTP 드래프터; CPU 전문가 구성에서 MTP 이득은 비평 C10 기준 **미확정 → 로컬 측정**) 또는 ModelOpt NVFP4 임포트 — 둘 다 공개 KLD 가 없으니 자기 한국어/영어 프롬프트로 `--kl-divergence` 비교. KV 양자화 시 release 빌드의 FA 커널은 `q4_0-q4_0; q8_0-q8_0; f16-f16; bf16-bf16` 쌍만 컴파일(비평 C16) → `-ctk q8_0 -ctv q4_0` 같은 비대칭 쌍은 느린 폴백; `q8_0/q8_0` 또는 `GGML_CUDA_FA_QUANTS` 자가 빌드. `--moe-cache-cpu-share`(PR #30966)는 **2026-11-04 기준 미병합**(RTX 3070 8 GB 35→62.4 tok/s 수치는 PR 브랜치 빌드 전제).
3. **하드웨어 네이티브 각도**: 이 카드의 FP4 텐서코어는 llama.cpp(MXFP4/NVFP4 W4A4 MMQ, 2025-12 / 2026-04 이후), vLLM(CUTLASS sm120 NVFP4 GEMM, Triton MXFP4 MoE), TRT-LLM(sm120 행)으로 닿는다. **프리필 15~30 % 가속**; 디코드는 448 GB/s 메모리 바운드로 포맷 무관 → 먼저 최적화할 것은 *가중치* 포맷의 바이트당 품질(EXL3 > 캘리브레이션 NVFP4 ≈ UD-Q4_K_XL > Q4_K_M > IQ4_XS > RTN FP4).
4. **직접, 잘 양자화하기**: 인도메인 채팅(한국어+영어+코드) imatrix(`scripts/30_imatrix.sh`), `--show-statistics` 로 고첨도 텐서 식별, `ffn_down_exps`/어텐션/공유 전문가 `--tensor-type` 승격(`scripts/40_quantize.sh`), KLD 기반 선택(두뇌는 ≤ 0.03, 크기가 강제하면 ≤ 0.06; `scripts/50_eval_kld.sh`). 후보 하나에 **pre-SINQ** 재매개화를 `llama-quantize` 앞에 적용해 KLD 가 내려가면 채택.
5. **기대하지 말 것**: 비중국 네이티브 삼진 7B+ 모델, Gemma 4 E2B/E4B EXL3, `llama-quantize` 의 imatrix 인지 NVFP4, Blackwell vLLM 의 INT8 W8A8.
