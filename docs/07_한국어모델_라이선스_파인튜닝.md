## 1. 결론 10줄

1. 8GB 에서 **돌아가고 · 한국어 SOTA 급이고 · llama.cpp 가 지원하는** 한국 모델은 **Kanana-2 30B-A3B**(KMMLU 68.26, HAERAE 75.57; PR #19803 로 2026-02 지원)가 유일. 단, **Kanana License 는 "자사 서비스 운영"은 허용하되 모델 재배포·API 상품화·SI/온프렘 패키징·디바이스 탑재·MAU 1천만↑ 는 카카오 별도 계약**이라고 2차 자료가 전함(원문 미열람 [M]). "모델 자체를 파는" 제품이면 카카오(alpha.k@kakaocorp.com) 허가가 필요.
2. 완전 허용 라이선스의 한국어 모델: **Mi:dm 2.0 Base 11.5B / Mini 2.3B (MIT, 원문 확인 [H])**, **A.X 3.1 Light 7B (Apache-2.0, 자체 사전학습 [H])**, **Kanana-1.5 8B (Apache-2.0 [H])**. 한국 문화·지시 추종은 Mi:dm, 한국어 지식은 A.X 3.1 Light 가 동급 최강.
3. 글로벌 모델의 한국어는 **지식/문화 셋에서 한국 모델보다 10~20점 낮다**(KMMLU-Pro: Gemma 3 27B 50.7, Mistral Small 24B 51.0, Phi-4 44.8 vs 한국 30B 급 67~69). **Gemma 4 의 KMMLU 수치는 어디에도 없음** → 로컬 측정 필수. gpt-oss-20b 는 MMMLU-ko 75.7(번역된 MMLU)로 글로벌 중 최상이지만 한국 문화 지식은 아님.
4. 따라서 "영·한 전용 두뇌"는 **Gemma 4 26B-A4B(영어·추론·멀티모달) + Kanana-2 또는 Mi:dm(한국어 응대·문서) 라우팅** 이 가장 안전한 조합. 32GB RAM 이면 30B-A3B MoE 는 한 번에 하나만 상주.
5. 한국어 토크나이저 효율: Kanana-2/A.X 3.1/Mi:dm 은 Llama-3·Gemma(262K SentencePiece)·o200k 계열보다 **같은 한국어 문장에 1.3~1.5× 적은 토큰** → 같은 tok/s 에서 글자/초 ↑, KV 소비 ↓, 컨텍스트에 더 많은 한국어.
6. **제외**: LG EXAONE 3.5/4.0/4.5(NC 라이선스 원문 확인 [H]), SKT A.X 4.0(Qwen2.5 기반 [H]), Kanana-nano-2.1B(CC-BY-NC), HyperCLOVA X SEED Think 14B/32B(llama.cpp 미지원 + 14B Q4 ≈ 9GB), Motif-2-12.7B·VAETKI(llama.cpp 미지원, 라이선스 미확인).
7. **파인튜닝(QLoRA)은 8GB 에서 3~9B 급만** 가능(Unsloth 최소: 7B 5GB, 8B 6GB, 11B 7.5GB, 14B 8.5GB). Gemma 4 26B-A4B·gpt-oss-20b·Nemotron 3 Nano·Trinity 는 **추론 전용**(학습 바닥 14GB+).
8. **QAT 는 8GB 에서 ≤3B 모델만**(Unsloth QAT 는 bf16 베이스 상주 필수, `qlora` 모드 없음). 4~9B Korean 모델의 QAT 는 H100 1장 임대(Unsloth int4 QAT+LoRA 공개 실험이 H100 1장) 후 로컬 배포.
9. 8GB 에서 통하는 "QAT-lite": **EfficientQAT**(블록 단위 학습, Llama-3-8B w4g128 PPL 6.14→6.47), **QA-LoRA**(병합 후에도 INT4 유지), **LoftQ**(양자화 오차 흡수 초기화). 그리고 **Gemma 4 QAT-unquantized 체크포인트에 LoRA → 같은 Q4_0 블록으로 재양자화**("QAT 위의 QAT") 가 취미가가 구글 파이프라인에 가장 가깝게 가는 길.
10. 판매 시 법률: **AI 기본법(2026-01-22 시행)** §31 — 생성형 AI 사용 사전 고지 + 결과물 "AI 생성" 표시(사람이 인식 가능 또는 기계판독 + 1회 안내), 합성 미디어 라벨. 과태료 ≤ 3천만원이나 **최소 1년 계도기간**(2026-01-22~). 모델 가중치 공개 자체는 규제 대상이 아님.

### 4.3 추천 레시피: "QAT 위의 QAT" (Gemma 4, 8GB)
1. `unsloth/gemma-4-E4B-it-qat-q4_0-unquantized`(구글 QAT 파이프라인에서 추출된 bf16 가중치, Apache-2.0)를 `load_in_4bit=True` + LoRA(r 8~16)로 **한국어 SFT**(ctx 1~2K). [M — 공식 QAT-unquantized 저장소 존재는 미러로 확인, HF 원문 재확인 권장]
2. 어댑터를 bf16 로 병합(CPU 가능) → `convert_hf_to_gguf.py` → **QAT 가 겨눈 것과 같은 Q4_0 블록으로 재양자화**(`llama-quantize ... q4_0`; imatrix Q4_K_M 과 KLD 비교).
3. H100 1장을 1시간 빌릴 수 있으면 1단계를 Unsloth `qat_scheme="int4"`(또는 Q4_0 정확 모사 `IntxFakeQuantizeConfig`) LoRA 로 대체 → 구글 파이프라인에 가장 근접.
4. 교사 증류는 **오프라인**만(DistillKit top-k 로짓 캡처: 교사 Gemma 4 26B-A4B 를 llama-server `n_probs` 로 덤프 → 학생 E4B/E2B, 같은 토크나이저). Gemma 4 는 Apache-2.0 이라 증류 학생에 Gemma-ToU 류 전가 조항이 없음(Gemma 3 는 §1.1(e) 로 파생물).

### 4.5 imatrix 캘리브레이션에 한국어를 넣어야 하는 이유(증거)
llama.cpp 토론 #5263: "imatrix 를 쓰느냐가 어떤 텍스트냐보다 훨씬 중요", 실제 다국어(영+불) 혼합 텍스트가 표준 관행, 코드 포함 혼합 세트가 wikitext 단독보다 KLD 낮음, 10K→1M 토큰 사이 과적합 미미 [H]. Unsloth Dynamic 2.0: 30만~150만 토큰의 채팅형 혼합 세트, 위키 단독은 과적합 경고 [M]. 비라틴 문자(한글)는 양자화 손상이 더 크고 자동 지표가 이를 과소평가(Marchisio et al. 2024 [L, 기억]). → `calib/build_calibration_set.py` 기본 배합(한 40/영 35/코드 15/대화 10)과 **한국어 별도 KLD 평가**(`scripts/50_eval_kld.sh`, 평가 텍스트는 캘리브레이션과 다른 것)를 유지.
